# Testeur USB : erreur HTTP 404 — V11.5.1

Dans la V11.5, le lanceur pouvait ouvrir le serveur sur un port libre si 8765
était déjà occupé. Le testeur USB et le pont utilisaient encore 8765 par défaut.
Le testeur pouvait donc joindre un ancien serveur dépourvu de /api/usb/cdc.
Le 404 se produisait avant les échanges USB avec le firmware.

La V11.5.1 mémorise l’adresse réelle du serveur dans work/web_endpoint.json.
Le testeur et le pont du même dossier la retrouvent automatiquement, puis
vérifient le dossier, la version, l’empreinte du code et la capacité USB CDC
avant de demander la moindre opération. Le lanceur réutilise aussi un serveur
compatible qui tourne sur un port différent de 8765. Une adresse --url explicite
reste possible, avec vérification de version et de code.

En cas d’échec HTTP, le message indique maintenant l’URL et la route concernées.
Un ancien serveur donne une erreur de version explicite ; un serveur arrêté
ou une adresse locale non disponible donne un message de connexion.
Le testeur n’utilise pas 8765 comme solution de repli silencieuse.

## Procédure

Extraire la V11.5.1 dans un nouveau dossier, lancer OUVRIR_BANC_WEB_V11_5_1,
puis démarrer le moteur et lancer TESTER_USB.cmd du même dossier.
Il n’est pas nécessaire de fermer de force un ancien serveur d’un autre dossier.
Le pont CONNECTER_CPS.cmd propose désormais l’adresse automatique par défaut.

Avec la V11.5 existante, une solution immédiate reste de fournir l’adresse
exacte visible dans le navigateur :

    .venv\Scripts\python.exe cps_probe.py --url http://127.0.0.1:PORT

Remplacer PORT par le port réellement affiché. Si le bandeau indique une
ancienne version du banc, relancer la V11.5 avant de refaire ce test.

Les modifications de V11.5.1 concernent la sélection et la vérification du
serveur local. Le modèle USB et le protocole de programmation restent ceux
de V11.5 ; la validation du CPS Windows complet reste à faire sur le PC utilisateur.

Validation : 192 tests passent dans l’archive préparée. Un serveur réel lancé
sur un port attribué automatiquement a été retrouvé par cps_probe.py sans --url ;
l’identification OEM et une lecture mémoire avec contrôle de somme ont réussi.
Le lanceur CMD Windows n’a pas été exécuté dans cet environnement Linux.
Voir validation_v11_5_1.json.
